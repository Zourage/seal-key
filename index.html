Seal your API key

This page encrypts your API key, in your browser, before anything leaves it. What you send to Discord afterward is ciphertext — Discord never sees your key, and neither does this website, because this website never talks to a server at all.

What this page does, in plain English

You paste your API key and your Discord user id below. This page generates a fresh, one-time encryption keypair, combines it with the bot's public key to derive a secret only the bot can reproduce, and uses that secret to encrypt your key with AES-256-GCM. The result — a short block of unreadable text called a "blob" — is what you paste into Discord, not your key. Only the bot's private key, which never leaves the bot, can undo the encryption.

This is not a form that submits anywhere. There is no server behind this page. Everything above happens with your browser's built-in cryptography library (WebCrypto), running entirely on your own machine.

Don't take that on faith — check it yourself

A page that says "paste your API key here" looks exactly like a phishing page. You should not trust the paragraph above just because it says so. Here is the one check that actually proves it, and you do not need to be a programmer to run it:

  • Turn off your network — WiFi off, ethernet unplugged, airplane mode on — then reload this page and seal a key. It still works, end to end, blob and all. A page that talks to a server cannot do that with no network. If you have your browser's developer tools handy, open the Network tab before you reload: a full, successful seal makes no request to any address other than this page itself while you type or click "Seal my key" — no image request, no script, nothing sent out. (Your browser may still show one same-origin GET /favicon.ico as part of the page load if you are viewing this over http(s) rather than from a saved local file — that is your browser's own fallback behavior, not something this page's markup or script asks for, and it is not what this check is about.) That is the real proof, and it is one you ran yourself, not one this page asked you to believe.
  • Save this file and open it from disk. Use your browser's Save Page As, then open the saved .html file directly (the address bar will show a file:// path, not http:// or https://). It still works, because it isn't served by anything.
  • Read the source, if you can. Right-click this page and choose "View Page Source" (or press Ctrl+U / Cmd+Option+U). Everything is in one plain-text file, nothing is minified or obfuscated. This step takes programming knowledge to get real value from, and it does not by itself prove anything — reading code and being sure it does nothing unexpected are different skills. What actually backs this page: an automated test suite in this project's repository (tests/test_seal_page_is_local.py) pins this page's <script> and <style> blocks to their exact bytes and checks the surrounding markup on every change, and a Content-Security-Policy meta tag at the top of the source has your own browser enforce that same script pin at runtime — a modified script will not execute at all — plus the other restrictions described there. Neither one is a guarantee that holds up against someone editing this file and its test suite together — the network-off check above is the one that does not depend on trusting this file's author at all.

What happens to your key — the same disclosure the bot shows you

These four paragraphs are copied unchanged from docs/ARCHITECTURE.md §5, "The disclosure — exact user-facing wording." Read them before you paste anything below.

What happens to your key.

It is encrypted before it is stored, under a key held by this server. A database dump, a backup, or a stolen disk image does not contain a usable credential. It does not protect you from whoever runs this machine — see below.

What we do not promise.

This bot runs on a machine we do not own. Anyone with root on that machine can read the memory of a running process, and therefore can read your key while a request is in flight. No software running on that host can prevent that or prove otherwise. If a hosted service tells you it "cannot access your keys" without hardware attestation, it is wrong.

What to do about it.

Sign in with OpenRouter rather than pasting a key. That mints a key that belongs to you, is scoped to this app, has a spending cap you choose, and that you can revoke from your OpenRouter dashboard at any moment without asking us. If you must paste a key, paste one with a spend limit on it, and revoke it when you stop using the bot.

What you are accepting.

No reliability, no liability, no responsibility. This is best-effort software running on hardware we do not control: it can be down, wrong, or broken at any moment, and we owe you nothing when it is. Your key pays for every request the bot makes on your behalf, including the ones you did not intend — an agent that gets stuck in a tool-calling loop can spend real money before anyone notices, and we do not cap it. There is no ceiling here and no kill-switch. A spend limit set on your own key, at your own provider, is the only thing that actually stops it. Set one before you continue.

And backread is on your bill too: every time you ping the bot it reads the last 100 messages in that channel — everyone's, not just yours — and sends them to the model on your key. That is roughly 2,000–5,000 input tokens per ping before you have typed a word, and it means you are paying to put other people's messages into a model. Lower the number, or set it to zero, on your settings page.

Steps, start to finish

  1. Get an API key from your provider (OpenRouter is the default). Before you copy it, set a spend limit on it at the provider — see "What to do about it" above. There is no spend cap on the bot's side; the cap you set at the provider is the only one that exists.
  2. Find your Discord user id. If you've never done this before: open Discord's User Settings (the gear icon) → Advanced → turn on Developer Mode. Then close settings, right-click your own name or avatar anywhere in Discord, and choose Copy User ID. It's a string of digits, typically 17–19 of them. You cannot use this page without it — the id is baked into the encryption so nobody else's copy of your sealed key will work for them.
  3. Paste your API key and your Discord user id into the two fields below.
  4. Click Seal my key. This runs entirely in your browser and takes well under a second; nothing is sent anywhere.
  5. Copy the sealed blob that appears (use the Copy button, or select the text yourself).
  6. In Discord, open a direct message to the bot and send: /setkey <paste the blob>
  7. Delete the message you just sent, immediately. This is not optional and it is not the bot's job — bots have no "Manage Messages" permission inside a DM, so the bot cannot delete it for you even if it wanted to. Until you delete it, the sealed blob sits in your own Discord message history indefinitely. Deleting your message is the only thing that removes it.

This page contains no fetch, no XMLHttpRequest, no WebSocket, no form submission, and no reference — script, stylesheet, image, or otherwise, absolute or relative — to any address outside this file. It also ships a Content-Security-Policy (see the top of the source) that has your browser itself refuse any request or resource load a script here might try to add, and refuse any form submission. That policy also pins this page's own script to its exact bytes — a sha256- hash source in script-src — so a modified script simply will not run in your browser at all; that says nothing about someone serving you a different page with a different policy. One honest exception remains: a meta CSP cannot stop a script from navigating the tab (no browser ships a working navigate-to directive), so that guarantee instead rests on this repository's test suite (tests/test_seal_page_is_local.py), which pins the same script bytes and checks the surrounding markup on every change, and is documented there, including what it does and does not cover. The one check that does not ask you to trust either this page or that test suite is the "turn off your network" step above — run it yourself before you paste a key.
